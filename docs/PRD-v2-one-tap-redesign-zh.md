# 换装相机 v2.0 产品需求文档

## 一键房间改造

---

## 摘要

换装相机 v2.0 消除意图与价值之间的所有摩擦。用户上传照片，立即获得AI设计的房间效果图和可购买的商品推荐。无需任何决策。无需等待即有回报。

**核心洞察：** 在展示价值之前要求用户做的每一个选择，都是让他们离开的机会。AI比用户更清楚什么风格适合他们的空间——让AI来决定。

**成功指标：** 首次价值时间 < 30秒（从约2分钟降低）。

---

## 问题陈述

### 现状
| 步骤 | 用户行为 | 摩擦点 |
|------|----------|--------|
| 1 | 浏览落地页 | 认知负担："这是什么？" |
| 2 | 上传照片 | 付出但无回报 |
| 3 | 选择房间类型 | 决策疲劳开始 |
| 4 | 选择风格（5个选项） | 选择悖论——用户不知道自己想要什么 |
| 5 | 选择预算（4档） | 没有上下文的抽象决策 |
| 6 | 点击生成 | 终于开始产生价值 |
| 7 | 等待30-60秒 | 焦虑，看不到进度 |
| 8 | 查看结果 | 第一次获得价值 |

**问题：** 6次交互，超过2分钟才能获得任何价值。

### 用户心理
- 用户不知道"斯堪的纳维亚风"和"波西米亚风"在*他们的*房间里是什么样子
- 没有看到每个档位能产出什么效果，预算选择毫无意义
- 每一个必须做的决策都是一个流失机会

## 功能需求

### FR-1: 单一动作上传流程

**触发条件：** 用户拖拽/选择图片文件

**即时响应：**
1. 显示图片预览
2. 展示"正在分析您的空间..."状态
3. 自动启动后端处理流程

**无需用户做任何决策。**

### FR-2: 生图模型直接决策（零中间环节）

**核心原则：不经过LLM分析，图片直接发给生图模型。**

生图模型本身具备图像理解能力，让它在生成时自主判断最适合的风格，省掉"先问LLM该用什么风格"这一跳。

后端 `POST /api/v2/transform` 仅接收：
```json
{
  "image_id": "string"
}
```

**处理流程：**
```
用户图片 ──直接──► 生图模型（自主判断风格并生成）──► 效果图 ──► LLM识别物品 ──► 匹配商品
```

**生图Prompt设计：**
```
根据这张房间照片，生成一张软装改造后的效果图。
自动判断最适合这个空间的设计风格。
保持房间原有结构、墙面、地板不变，
只改变软装（沙发、窗帘、地毯）、灯光、装饰品。
输出高质量、真实感的室内设计效果图。
```

**为什么这样做：**
- 减少一次API调用延迟（省掉LLM分析环节）
- 生图模型看到原图时，自然会生成与空间协调的风格
- 用户更快看到结果

### FR-3: 带覆盖选项的结果页

**主要展示：**
- 前后对比滑块（保留）
- 带联盟链接的商品网格（保留）

**次要操作：**
- "换个风格"按钮
- 点击后展开内联风格选择器
- 使用用户选择的风格重新生成
- 预算仍由AI决定（或根据用户需要开放）

**UI状态：**
```
[结果页]
    │
    ├── 默认：完整结果展示
    │
    └── 点击"换个风格"后：
            │
            ├── 展开风格选择器（5个选项）
            ├── 可选：预算覆盖开关
            └── [重新生成] 按钮
```

### FR-4: 加载体验

**要求：**
- 带阶段标签的进度指示器
- AI"思考中"文案实时更新：
  - "正在分析房间结构..."
  - "为您的空间选择理想风格..."
  - "生成改造效果..."
  - "匹配推荐商品..."

**不要百分比——用户不在乎47%还是52%。**

使用阶段式进度：
```
[■■■□□] 分析中 → [■■■■□] 设计中 → [■■■■■] 完成
```

## API变更

### 新端点：`POST /api/v2/transform`

**请求：**
```json
{
  "image_id": "uuid"
}
```

**响应（通过SSE或轮询流式更新）：**
```json
{
  "task_id": "uuid",
  "status": "completed",
  "generated_image_url": "https://...",
  "shopping_list": [
    {
      "name": "北欧风布艺沙发",
      "category": "家具",
      "price": 2800,
      "affiliate_link": "https://..."
    }
  ],
  "total_price": 4200
}
```

### 修改后端点：`POST /api/v2/transform/override`

用于"换个风格"流程：

**请求：**
```json
{
  "image_id": "uuid",
  "style": "boho",
  "budget": null  // null = 让AI重新决定
}
```

## 边界情况

| 场景 | 处理方式 |
|------|----------|
| 模糊/昏暗图片 | 仍然展示结果 + 温和提示："为获得更好效果，请尝试光线充足的照片" |
| 非房间图片 | AI检测并显示错误："这看起来不像房间。请上传您居住空间的照片。" |
| 用户上传后离开再返回 | 将 `task_id` 存储在 localStorage；返回时恢复轮询 |
| AI风格选择看起来不对 | "换个风格"始终可见——用户有控制权 |

## 实施阶段

### 阶段1：前端简化
- 从步骤1移除选择UI（房间类型、风格、预算）
- 上传完成后自动触发生成
- 在结果页添加"换个风格"

### 阶段2：后端流程重构
- 创建 `/api/v2/transform` 统一端点
- 图片直接发给生图模型，prompt内置风格自动判断
- 生成完成后，LLM识别效果图中的物品
- 匹配商品并返回

### 阶段3：优化打磨
- 优化加载体验
- 添加"分享你的改造"社交钩子
