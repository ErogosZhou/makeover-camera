# 换装相机 Makeover Camera — 参赛作品说明

> 一张照片，看见家的另一种可能。
> 拍下你的房间，AI 当场"换装"：生成改造效果图，并给出可一键下单的同款商品清单。

## 一、作品定位

**换装相机**是一款 AI 家装软装改造工具。用户只需上传（拍摄）一张房间照片，AI 自动完成"空间理解 → 设计方案 → 效果图渲染 → 商品匹配"全流程，约 1 分钟内交付：改造前后对比图 + 每件物品可购买的真实商品清单。

**未来形态：StepX Neo 智能体原生 Builder App。** 以 STEPX Neo 的相机为输入入口、以阶跃 step 模型为大脑、以手机原生支付为交易闭环，做"意图即服务"在家装场景的垂直落地（详见第六节）。

## 二、核心功能

1. **一键改造（零决策）**：上传照片即出结果，无需选择风格/预算，AI 根据空间光线、色调、比例自动决策
2. **设计文案实时呈现**：AI 的设计方案以打字机效果 + 全屏歌词动画流式展示，把等待时间变成内容消费
3. **设计即商品**：效果图中的每个物品实时匹配拼多多真实商品（价格、销量、推广链接），并生成带二维码的商品卡片，可直接分享
4. **换风格重生 / 历史记录 / 收藏 / 微信·Google 登录**
5. **流式并发体验**：设计文案生成、效果图渲染、物品识别与商品匹配多路并发，首内容 3 秒内可见

## 三、技术方案与实现思路

**架构**：FastAPI 异步后端 + 原生 H5 移动端前端（Tailwind + Alpine.js，无构建依赖），任务状态机驱动（pending → generating → matching → completed），前端轮询 + 流式回调。

**AI 三阶段流水线**（V2 主流程）：

```
用户照片
   │
   ├─► ① step-5-preview（StepFun）视觉理解
   │      输出：改造设计方案（约 380 字）+ 8-10 个物品关键词
   │      → 设计文案立即回传前端，启动打字机展示
   │
   ├─► ② doubao-seedream（火山引擎）图生图
   │      输入：原图 + 设计方案，输出 2K 效果图（完整图 + 缩略图双版本）
   │
   └─► ③ 拼多多多多进宝
          每个物品关键词 → 真实商品搜索、按销量排序、推广转链
```

**关键工程设计**：

- **多模型可插拔**：VLLM 层抽象 `provider`（ark 豆包 / stepfun step-5-preview 一键切换），生图层抽象（seedream / gemini），业务代码零改动适配不同模型
- **成本与速度优化**：多模态图片自动压缩（512px / JPEG q85，token 成本降约 80%）；三阶段并发流水线；API 失败自动重试与降级（VLLM 失败 → fallback 方案；COS 不可用 → 本地存储）
- **新模型适配实践**：seedream 5.0 移除流式参数改造；step-5-preview 按 OpenAI 兼容协议接入（`reasoning_effort=low` 平衡推理质量与延迟）

## 四、作品创新点

1. **产品形态创新**："换装相机"——"装"的双关（装修 / 换装），把"给房间换装"做成拍照即得；名字致敬哆啦A梦同名道具，零解释成本
2. **意图即服务的家装版**：从"看到"到"买到"全自动闭环——这正是 StepX Neo 所倡导的"意图即服务"的垂直场景预演
3. **设计文案即体验**：将 AI 的设计思考过程产品化（打字机 / 歌词动画），差异化等待体验
4. **可插拔多模型架构**：同一套业务代码切换不同视觉/生图模型，对 Step 模型迭代零成本跟进
5. **工程完成度**：全流程真实可用（非概念验证），含登录、历史、收藏、商品卡片、Agent 搜索 API 等完整周边

## 五、Step 模型使用情况

| 项目 | 说明 |
|---|---|
| 使用模型 | **step-5-preview**（阶跃星辰旗舰多模态基座，600B MoE / 27B 激活，1M 上下文，原生视觉） |
| 接入方式 | StepFun 开放平台 Step Plan 通道，OpenAI 兼容 `/chat/completions`，多模态消息（base64 图片 + 文本） |
| 用途一（核心） | **房间照片视觉理解与改造方案生成**：分析光线、色调、空间比例，输出结构化设计方案 + 物品关键词数组（自定义 META_PROMPT，温度 0.9 保设计多样性，`reasoning_effort=low` 控延迟） |
| 用途二 | **效果图物品识别**：对比原图与效果图，识别新增可购买软装物品（服务 V1 流程与 Agent 搜索 API） |
| 实测效果 | 单次调用输出约 380 字设计方案 + 10 个物品关键词，物品识别准确，支撑完整购物清单 |
| 为什么选它 | 原生多模态视觉推理强、成本低（输入 $1/M tokens）；与阶跃生态（StepX Neo）天然协同 |

> 生图模型使用 doubao-seedream（火山引擎），商品数据使用拼多多多多进宝；VLLM 层的 provider 抽象使 Step 模型可无缝替换或回退。

## 六、StepX Neo Builder App 规划（未来形态）

本项目将作为 **StepX Neo 上的 Builder App** 演进，核心是"硬件 × 模型 × 原生支付"三位一体：

1. **硬件结合**：以 STEPX Neo 的相机为天然输入入口——对着房间拍一张，即触发改造流程；手机背屏可作为智能体状态屏，实时呈现"分析中 / 渲染中 / 匹配中"等任务进度
2. **智能体原生**：接入 Amoo / Step AOS 能力——用户直接说"把这客厅改成日式"，由智能体调度本应用完成全流程；借助端云协同，端侧负责拍照、预览、历史管理等轻任务，云端负责 step-5-preview 与生图重推理；长期记忆可沉淀用户风格偏好，越用越懂
3. **原生支付闭环**：效果图购物清单中的每件商品，通过 STEPX Neo 原生支付能力（如支付宝深度集成，"确认金额即完成付款"）一键下单——从 AI 效果图到真实包裹，端到端完成"意图即服务"
4. **生态卡位**：家装是"看到即想要、想要即购买"决策链最短的品类之一，非常适合作为智能体手机上的示范性 Builder App

## 七、本地运行

```bash
cd backend
python3.11 -m venv venv
./venv/bin/pip install -r requirements.txt
cp env.example.txt .env   # 填入 StepFun / 火山引擎 / 拼多多 API Key
./venv/bin/uvicorn main:app --host 0.0.0.0 --port 9000
```

浏览器打开 `http://localhost:9000`，上传房间照片，约 1 分钟获得完整结果。
